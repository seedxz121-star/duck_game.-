# مزرعة البط – لعبة تيليغرام

## الملفات
- `index.html` : واجهة اللعبة (Mini App)
- `server.py` : السيرفر (FastAPI + SQLite) مع التحقق من توقيع تيليغرام
- `bot.py` : البوت الذي يفتح اللعبة

## التشغيل
1. **البوت:** في @BotFather أرسل `/newbot` واحفظ التوكن.
2. **تثبيت:** `pip install -r requirements.txt`
3. **السيرفر:**
   ```
   export BOT_TOKEN="توكنك"
   uvicorn server:app --host 0.0.0.0 --port 8000
   ```
   يجب أن يكون على رابط **HTTPS** عام. أسهل خيار: استضافة Render أو Railway أو Fly.io (ترفع المجلد كاملاً). للتجربة المحلية: `cloudflared tunnel --url http://localhost:8000`.
4. **البوت:**
   ```
   export BOT_TOKEN="توكنك"
   export WEBAPP_URL="https://رابط-السيرفر"
   python bot.py
   ```
5. افتح البوت، أرسل `/start`، واضغط «العب الآن».

## النشر على Render (الأبسط: خدمة واحدة)
السيرفر يستقبل رسائل البوت عبر webhook، فلا حاجة لتشغيل `bot.py` (يبقى للتجربة المحلية فقط).
1. ارفع المجلد إلى مستودع GitHub (الملف `.gitignore` يمنع رفع قاعدة البيانات).
2. في Render: **New ← Blueprint** واختر المستودع، فيقرأ `render.yaml` وينشئ الخدمة والقرص.
3. أدخل المتغيرات في لوحة Render: `BOT_TOKEN` (من BotFather)، `BOT_USERNAME` (بدون @)، `WEBHOOK_SECRET` (أي نص عشوائي طويل)، و`WEBAPP_URL` (رابط الخدمة بعد إنشائها، مثل `https://duck-game.onrender.com`) ثم أعد النشر.
4. اربط البوت بالسيرفر بفتح هذا الرابط في المتصفح مرة واحدة:
   `https://api.telegram.org/bot<TOKEN>/setWebhook?url=<WEBAPP_URL>/webhook/<WEBHOOK_SECRET>`
5. في BotFather: Bot Settings ← Configure Mini App ← ضع `WEBAPP_URL`.
6. جرّب: افتح البوت وأرسل `/start`.

تحذير: لا ترسل التوكن لأحد ولا تضعه في GitHub. إن تسرّب فاستخدم `/revoke` في BotFather.
الخطة المجانية في Render تحذف الملفات عند كل إعادة تشغيل وتنام بعد 15 دقيقة، فتضيع قاعدة البيانات؛ استخدمها للتجربة فقط، واستخدم خطة مدفوعة مع القرص (كما في `render.yaml`) للتشغيل الفعلي.

## الإحالات والمهام
- في @BotFather: `/mybots` ← اختر البوت ← Bot Settings ← Configure Mini App ← ضع رابط السيرفر. هذا ما يجعل رابط الدعوة `t.me/البوت?startapp=ref_...` يفتح اللعبة مباشرة.
- أضف متغير `BOT_USERNAME` (اسم البوت بدون @) إلى السيرفر.
- مهمة الانضمام للقناة اختيارية: ضع `CHANNEL=@اسم_القناة` وأضف البوت مشرفاً فيها.
- مكافأة الإحالة تُمنح مرة واحدة فقط عند أول دخول للاعب الجديد، ولا تُحسب دعوة النفس.
- المهام تُعرَّف في قاموس `TASKS` أعلى `server.py`، وأي مهمة جديدة تُضاف بسطر واحد.

## الصور والسوق
- صور البط رسوم SVG أصلية في `static/ducks/`. لاستبدالها بصورك: ضع ملفات بالأسماء نفسها (`duck` و`chick` و`golden` و`royal` و`fan` و`wizard` و`astro` و`egg` و`egg_crack`) وإن كانت PNG فغيّر `.svg` إلى `.png` في `index.html`.
- السوق: عرّف البط المعروض وأسعاره في `SHOP` أعلى `server.py` وأسماءهم في `NAMES`، ثم أضف صورة بالاسم نفسه. الشراء يتم في السيرفر بخصم العملات.

## الدخل السلبي
- كل بطة تدرّ عملات كل ساعة حسب `INCOME` في `server.py`، وتتراكم الأرباح حتى `CAP_HOURS` (3 ساعات) ثم تتوقف حتى يضغط اللاعب «اجمع». هذا يشجعه على العودة عدة مرات يومياً.
- تُثبَّت الأرباح قبل أي تغيير في عدد البط (فقس أو شراء) حتى لا تُحسب بأثر رجعي.
- لتوازن الاقتصاد: بطة المشجع تسترد ثمنها خلال نحو 40 ساعة. عدّل الأرقام كما تريد.

## لوحة الترتيب
- تعرض أفضل 20 لاعباً حسب العملات أو عدد البط، مع ترتيب اللاعب نفسه ولو كان خارج القائمة.
- تظهر الأسماء الأولى فقط (حتى 16 حرفاً) ولا تُكشف أي معرّفات. إن أردت إخفاء الأسماء، غيّر `name` في `server.py` إلى «لاعب».
- مع آلاف اللاعبين أضف فهرساً: `CREATE INDEX idx_coins ON players(coins)`.

## ملاحظات
- كل المنطق (الفقس، العملات، المكافأة) يجري في السيرفر، فلا يمكن التلاعب به من الواجهة.
- للتجربة في المتصفح بدون تيليغرام: `DEV=1` (لا تستخدمه في الإنتاج).
- `game.db` يُحفظ بجانب السيرفر؛ على Render/Railway أضف قرصاً دائماً (Volume) وإلا يُمسح عند إعادة النشر.
- لاحقاً: المهام، الإحالات، السوق، وصور حقيقية للبط.
